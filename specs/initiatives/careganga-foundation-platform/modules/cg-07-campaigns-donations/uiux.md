## Original six-step campaign screen and action behavior (US-001)

**Step 1 — Basic Details (A13):** Label campaign title, generated human business code, campaign type, short and full explanation, approved status/draft vs publish, tags; filter unsafe HTML/URLs; no admin technical IDs shown. **Step 2 — Project & Category (A14):** Genuine CG-07 cause/category, current CG-02 state/district/area/branch, optional CG-05 same-root approved current project/event. If CG-05 absent, a meaningful **General Foundation Campaign** still saves without fake project. “Target beneficiaries” is an explicitly labelled **planned estimate/target group**, never a private CG-06 recipient lookup or claimed verified assisted count.

**Step 3 — Team & Assignment (A14):** Original coordinator/team selector of real eligible CG-01 accounts/current branch, optionally active CG-04 volunteers **only when that source exists** and current policy allows; no fictitious team or volunteer ID entry. **Step 4 — Budget & Targets (A15):** Campaign target/expected cost/period and current applicable currency. Target is fundraising goal, **not CG-09 approved budget or amount received**; show real CG-09 approved allocation only when specifically sourced. **Step 5 — Documents & Media (A15):** Validated CG-19 cover and consented protected media, private vs eligible public use, upload pending/failed/scan status, ALT; an optional text-only campaign works before file is attached if policy allows. **Step 6 — Review & Submit (A15):** Immutable digest preview, corrections/back, Save Draft and Submit for Verification; actual CG-03 pending/returned/rejected/approved status is separate from CG-18 CMS Draft/Submitted/Published/Withdrawn. Editing after approval creates a new revision; show a meaningful “Needs re-approval” state instead of silently retaining active public coverage.

**A12 action feedback:** Role-hidden Launch/Edit/Withdraw/export controls, permission-denied API on bypass, responsive sticky step toolbar and narrow layout without losing Save Draft/Back/Next. Invalid area, dates, source project, private image/expired consent, or foreign branch are identified at affected step and on final summary. Two editors cause safe version-conflict refresh, not overwritten content. Public Donate CTA disappears on stop/close/source or CMS revocation, including stale Web/native cached cards; a late already-accepted payment is still reconciled.

## Original A16–A18 donation and receipt journey (US-002/003)

**Public / donor:** Open published eligible Foundation campaign (or explicit General Donation) → enter valid permitted amount/contact and consent → select truly available channel → receive donation business reference and current payment request/link status → provider checkout only when real approved merchant configured → return shows **Awaiting confirmation**, never “Paid” based only on browser redirect → backend verified/payment posted state → **Receipt being prepared** until actual CG-19 issuance → private receipt/proof available to owner.
