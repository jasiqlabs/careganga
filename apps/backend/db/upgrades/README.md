# Future upgrades only

V1 baseline is frozen; upgrade 10000 adds CMS first-install provenance. Fresh installs use ../baseline/schema.sql. Add a reviewed, forward-only file with a unique numeric prefix above 9999 (for example 10000_cg01_description.sql) only for an actual schema change. Never edit a released file. SQL must be transactional; no BEGIN/COMMIT/ROLLBACK, psql meta commands, COPY or nontransactional DDL. Use dollar-quoted routine bodies. Back up before applying to an existing database. Normal backend startup invokes the guarded release engine to apply pending upgrades once. Already-current startup is read-only; the historical archive is never replayed. New relations require an explicit reviewed runtime grant policy in the release engine; do not grant ownership, schema CREATE, or migration-ledger writes.
