### CG-02 introduced owner extensions — real visible outcomes

**CG-03 extension (US-002-QA14):** The wizard's Submit action first freezes one actual CG-02 reviewed source revision and verified evidence versions, then awaits an existing or newly created typed `BRANCH_REGISTRATION` CG-03 case. Current-authorized distinct Super Admin final approval and CG-02 activation appear as **two separate states**. An unavailable process, revoked reviewer, changed source/digest, returned/new revision or indeterminate case creation displays a recoverable truthful reason and read-only prior case history; never expose a fabricated review timeline or activation.

**CG-19 extension (US-002-QA15):** Steps 3–4 on Admin Web and Internal Android permit genuine scoped protected draft uploads **without first obtaining a CG-03 case**. Distinguish selected/uploading/upload-unconfirmed/scanning/validated/rejected/revoked/replace-version, and show a source-authorized preview only after current CG-19 permission check. Required photos, registration records and agreement remain explicit by step; submission is disabled only for **actual missing/invalid required evidence**, not for an unavailable future-only feature. A returned application reopens editable evidence as a new version while previous reviewed snapshots stay read-only. Expired or revoked preview requires reauthorization and a human-readable denied/retry action; no raw object key/token is ever displayed.

**CG-01 scope extension (US-002-QA02/12):** An assigned branch-manager label is not an access grant. Web and Android show only current authorized branches, departments and file previews; a newly active, inactive, closed or foreign branch cannot silently create root permissions. Denied/revoked/current-scope changes refresh authoritative status and clear stale option results.
