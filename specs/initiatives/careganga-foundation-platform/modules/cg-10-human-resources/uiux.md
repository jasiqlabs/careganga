## 1. User roles and exact channel ownership

**Foundation HR/Admin Web:** Authorized HR/line manager/supervisor/internal approver uses original CareGanga searchable sidebar, blue selected item, title/toolbars, dense but readable table, status KPIs, filter chips, multi-stage form, right-side drawer, original template preview; actual CG-01 grants and current CG-10 employee/CG-02 branch scope decide visible actions. Foundation Admin employment/private fields and reviewer comments are NEVER exposed to normal employee/public pages. A role option in HR is a **CG-01** role proposal, not a second HR grants editor.

**Internal Android:** Employee's **own** profile/assignment and status, attendance, leave application/history and permitted corrections, own published appraisal/status/resignation requests, issued private letters/card and eligible allowance if genuine CG-09 source exists. Allowed supervisor actions may use existing CG-03 approval native case workflow; do not invent an entire second HR Admin app or approval engine. Native actual screens use same validated DTO and accessible CareGanga tokens/Back/keyboard/offline states, not a protected desktop WebView.

**Public Next.js / Public Android:** No raw employee directory, attendance, private appraisal, bank, salary, HR letters or role/branch management. CG-10 US-001 supplies only optional allowlisted consented current employee public-safe identity/status when an *actual CG-18* editorial team biography later links it; CG-18 controls editorial publication and must not be required for CG-10 onboarding. Public anonymous QR for a valid employee ID card, if provided by **CG-19**, reveals minimum status-only result and no personally identifiable employee record.

**Shared source:** One `packages/design-tokens` canonical original CareGanga color/typography/spacing/icon/radius/motion token implementation reused by apps/web and apps/android-internal. Do not invent separate HR palette. Source image establishes visible layout, **not** animation duration/easing; honor reduced motion and accessibility. ## 3. US-001 — Employee enrollment, six-stage reference, real directory

**Actual application wizard:** B27/B28 shows reference stage labels `Registration → State Verification → Zonal Head → HR Verification → Super Admin Approval → Employee Activated`; **display only those stages that exist in the actual versioned CG-03 EMPLOYEE_ENROLLMENT process.** Author may Save Draft; actual Submitted, Under Review, Returned for Correction, Rejected, Final Approved, PENDING_ACCESS and ACTIVE are distinct from an input-success toast.

Field groups with actual explicit labels, validation and permissions:
1. Personal identification: name, parents' names where lawfully needed, DOB, gender, blood group (sensitive optional per policy), phone, email, state/district/block/PIN/address, CG-19 validated identity/photo evidence.
2. Employment: employment type, REAL CG-02 active Foundation branch, genuine branch department, designation, manager from real approved CG-10 option, work location, joining/hire date and current employee status.
3. Access proposal: permitted CG-01 role options; do not display or grant a hypothetical custom/root role. HR form selects a proposal; actual CG-01 grant only after approved source and permission.
4. Restricted finance: proposed salary **as HR request-only**, bank account holder/number confirmation/IFSC/UPI/account type via restricted validated token source; no CG-11 salary structure calculation yet.
5. Protected uploads: private photo, Aadhaar/PAN as policy permits, address/education/experience/resume/agreement via real CG-19 upload/scan. Display Original file initiated → Scanning → Validated/Rejected/Unknown, private preview only by current eligible reviewer.
6. Final summary: original approved branch/department, current document count/status and CG-03 case stage, not an invented active employee.

**Directory:** B20 HR Home real cards/department/status/staff attendance/leave where actual corresponding story exists; B30–B31 name/role/branch/state/department/status filters, finite pagination, visible human staff ID and designation only when eligible. Distinguish candidate Pending, Probation, Active, On Hold, Resigned/Inactive and PENDING_ACCESS. No private Aadhaar/bank in list or generic option. **Internal Android** employee sees current own approved employment status/branch designation/role-safe fields, pending access reason where authenticated but no other staff KYC directory.

**Errors and responsive:** Wrong branch/closed department, manager self/circular, duplicate applicant/account and CG-03 not configured → precise safe field/status. Desktop original grouped form/status side panel, tablet readable split/stacked, narrow full-width editable steps and sticky action where supported. Primary actions Save Draft, Preview (private), Submit for Review, Reopen Correction and View Status differ from an authorized CG-03 Approve. Missing native login/owner case returns unavailable, never "Employee Activated" before real status.

## 4. US-002 — Attendance/calendar/leave native self-service

**B22–B23 Attendance Admin:** Month/year selector, one live daily attendance calendar legend Present/Absent/Late/Leave/Weekly Off, department/employee search, employee×date matrix, row details and actual Correction Requests panel. Shift Settings form for start/end, break, grace and weekly off, effective date and branch time zone. For an overnight shift show correct business day/time range; B20 Attendance count and B21/B24 leave summary derive the same canonical source, not UI duplicates.

**B21/B24/B25 Leave:** Leave Overview/Balance/Distribution/Upcoming Leaves and real status-separated pending/approved/rejected list with applicant/type/period/days/reason (private)/authorized review controls. Leave policy days, carryover, weekly-off counting, half day if configured, same employee current approved balance, accurate entitlement and overlapping effective dates. A pending or rejected request doesn't decrement approved leave as if effective. Correction/future-year leave follows immutable original policy version and CG-03 approval, no payroll run needed.

**Internal Android native:** My Attendance and My Leave, day calendar, Apply Leave type/dates/reason and optionally medical proof via actual CG-19 source; current status + safe balance, requested correction/approval history. Accessible calendar/labels/focus, keyboard/BACK, offline draft versus server-accepted 202, and stale response status reconciliation. Employee cannot self-approve or see supervisor's team unless current CG-01 grant.

## 5. US-003 — Performance, transfer, promotion and resignation/exit

**B26:** Performance dashboard true score count, pending periods; Review/New Appraisal panel employee/period, three sliders Goal & Delivery, Competency, Attendance & Conduct, overall result with genuine configured scoring rule, strengths/improvement private text and Save Draft/Submit. The source audit does **not prove a particular scoring weight**. Submitted performance is immutable, reviewer current branch/manager scoping enforced.

**B44–B45:** Transfer/Promotion stepper Initiated → Approval → Approved → Completed **only for actual corresponding CG-03 process state**. Current designation/department/branch/role/manager vs proposed role/designation/branch/manager and *confidential salary proposal*, effective date/reason; real source review and old/new appointment history. An approved but **future-effective** transfer is not already applied. Current employee/session and role access are changed safely through CG-01 once actual effective CG-10 assignment is committed. Without CG-11 payroll, proposed salary is **NOT_APPLIED**, never silently mutates payroll structure.

**B46–B48:** Resignation search/status tabs and New Resignation drawer (employee, exit type, submission/last work dates, reason/remarks) and right detail with HR/Asset/Handover/Finance clearance flags. A finance clearance must show Verified only with real authorized proof; absent CG-09/CG-11 sources is NOT_VERIFIED/NOT_AVAILABLE, not PAID. Withdraw/Save Changes/Complete Exit actions respect real CG-03 final decision and CG-01 scope revocation at effective date. Native Internal Android only allowed own request/status and released review, not Foundation HR approval panel.

**Error states:** Wrong/closed destination, old assignment version, duplicate conflicting transfer, self-review, exit when still pending/approved future transfer, request approval not actual, revoked old branch, current role/source unavailable. User-facing status text and precise next action; no technical employee/role IDs.
