A. Global developer rules — mandatory
   Automated transactional sender: noreply@careganga.com. Replies and support conversations must route to an
    approved, monitored team inbox.
   Never email a plaintext password. When an employee/member/volunteer is given login access, send the login email
    and a secure, single-use, time-limited password setup/reset link. Show role, state, district, subdivision/block and
    branch scope where relevant, but never include a password.
   Member payment receipt: send only after the payment provider confirms success. Attach the official membership
    payment receipt PDF and include transaction/reference number.
   Donation workflow has NO donation approval stage. After successful provider confirmation, record the donation and
    send the donation slip/receipt PDF immediately. Include donation transaction/reference details. Handle possible
    duplicate donations through a separate duplicate-payment case and refund workflow.
   Refund status must distinguish Requested, Under Review, Approved, Processing, Processed, Failed and Rejected.
    Say 'refund processed' only after the payment provider confirms processing.
   Member final approval email must include Member ID, member type, issue date, validity/expiry date and attach
    Member ID Card PDF, Welcome Letter PDF and Membership Certificate PDF.
   Volunteer final approval email must include Volunteer ID, approval/issue date, validity/expiry if applicable and attach
    Volunteer ID Card PDF, Welcome Letter PDF and Volunteer Certificate PDF. Volunteer registration is free.
   Employee documents received is not the same as documents verified or employee approved. Offer, approval,
    appointment and joining letters must only be attached when approved, generated and issued in the system.
   Designation/office-bearer approval email must include Designation ID, certificate number, role/designation, state,
    district, subdivision/block or jurisdiction, issue date and expiry date/N/A, with approved certificate attached.
   Role, designation, jurisdiction or promotion changes must trigger an audit event. If the change requires a new ID
    card/certificate/letter, issue the updated approved PDF and mark the old version superseded.
   Salary slip email is confidential and employee-only. Salary generated/approved and salary disbursed/paid are
    separate events; send the payment confirmation only after bank/provider confirmation.
   Support requests must receive a unique Ticket/Service Request ID. Send acknowledgement, status changes and
    closure email. Verify requester and registered destination before resending personal documents.
   Use event-based idempotency: a unique event ID + template ID + recipient + document version must not send
    duplicate logical emails. Delivery retries should be logged.
   Store delivery log: template ID, trigger event, recipient record, send time, provider status, retry count, attachment
    names/versions, initiating staff/system and related application/payment/ticket ID.
   Do not promise 80G/tax benefits unless the Foundation's current legal eligibility and approved receipt wording are
    verified. Avoid unnecessary sensitive personal information in subject lines.

K. Developer implementation checklist
   Create a database-backed Email Template Master with Template ID, version, language, subject, body, enabled flag,
    recipient type, trigger event, attachment rules and owning team.
   Create an event/trigger map for every template; trigger only after the relevant status is committed in the database.
   Create PDF generation and attachment checks. If required PDF generation fails, do not send an incomplete approval
    email; create an internal alert and retry safely.
   Generate unique IDs for applications, Member ID, Volunteer ID, Employee ID, Designation ID, certificate number,
    memo number, transaction reference, refund request and support ticket.
   Keep member/volunteer application decisions separate from document verification decisions. Keep employee
    document verification separate from employment approval and joining.
   Donation has no approval state. Send donation slip after provider-confirmed payment; possible duplicates go to
    duplicate review/refund flow.
   Schedule expiry/renewal reminders from saved expiry dates and policy. Cancel queued reminders after renewal;
    exclude Lifetime and N/A expiry.
   Role access must be authorised, least-privilege, scoped to state/district/subdivision/block/branch/department and
    auditable. Never email plaintext passwords.
   Support ticket states should include at minimum: New, Assigned, In Progress, Waiting for User, Escalated, Resolved
    and Closed; adapt names to actual portal statuses.
   Add an admin preview/approval for sensitive or legal letters and certificates; store approved PDF version and issuing
    authority.
   Add delivery provider status tracking, bounce handling, safe retries, duplicate suppression and audit logs.
   Test each template with sandbox payment/refund events, fake recipients, missing attachments, rejected applications,
    send-back flows, expiry dates and role changes before production.
