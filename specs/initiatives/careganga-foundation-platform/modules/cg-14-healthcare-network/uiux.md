## 3. US-001 — pending provider and own operating locations

**Admin Web entry**: "Healthcare Network" → "Providers" with authorized filters (type, registration stage, center count and area) and a true verified current count, not mock metrics. "Add Provider" launches an accessible stepwise grouped form, not necessarily an invented seven-stage wizard: Provider identity (legal name, true approved type, code, current contact) → center locations (display name/type, unique local code, genuine CG-02 state/district/block, PIN/address, optional validated coordinates, time zone) → permitted capabilities/facilities/opening hours → restricted registration/proof (CG-19 actual scan) → sensitive settlement destination (masked, separately scoped) → Review draft and Save. One provider may have two center cards; adding one does not clone a legal entity.

**Eligibility and preview:** Center account invitation is a legitimate current CG-01 account + CG-14 own-center affiliation with minimal PENDING_EDIT permission, not an email lookup trust. Own Center Portal can fill missing details while stage is pending. Distinguish Draft saved, File scanning, Evidence validated, Ready to submit, Submitted for later review; **US-001 does not pretend US-002 CG-03 provider approval exists**. Avoid auto-advancing publication after saving.

**Validation and errors:** Human labels for Legal provider name, Center display name, Center type, State, District, Block, PIN, Working hours, Phone/Email, Public address, document rights and Settlement details. Show duplicate code/revision conflict/permission denied/scan unavailable/current stored status, never raw constraint/database keys. On network-unknown submission show "Check this provider's current status" before repeat. Bank information never appears in public card, ordinary provider list or app cache.

## 4. US-002 — separate real verification, login and public visibility

**Admin Web Provider Review:** Searchable Pending/Returned/Verified/Rejected/Suspended tabs with actual source records; source header provider/legal code, center name/address, genuine proof statuses, immutable submitted version and CG-03 case outcome, reviewer notes displayed only by authorized current permissions. Actions **Return for correction / Reject / Approve verified** open explicit confirmation with reason and show true source outcome, not immediate published state. Two **distinct** Foundation permissions govern "Enable Center Portal access" (CG-01 account context + CG-14 affiliation) and "Publish public listing" (CG-14 authorized actual source), each with confirmed current status and withdrawal/suspend. A verified center with public publishing disabled is not searchable.

**Center Portal own progress:** Current status timeline, "Update requested information" only for returned/draft, correct scope and resubmission. An inactive provider cannot access its old privileged data. Never display private Foundation review decisions for another center or a fake center-wide approval count.

**Lifecycle feedback:** Submitted for review, Evidence scanning, Returned with allowed corrections, Rejected, Verified, Center login active, Public listing published, Suspended, Withdrawn, Approval unavailable, Conflict (source changed), Pending confirmation (unknown network). Public center-only information may be available from the real CG-14 public projection before US-004, but no fake doctor card.

## 5. US-003 — one doctor profile, many real centers and versioned fees

**Foundation Admin Doctor form:** Name, private verified contact, jurisdiction, professional registration number and evidence (CG-19), qualifications, specialties, experience years, short public biography and consented portrait; saved draft/immutable submitted version → CG-03 real doctor verification → verified/rejected/returned. Use human selection of genuinely current Center A/B from authorized options, not manual provider IDs. Display one professional identity and **two center association rows**; do not clone doctor registration data for each clinic.

**Center-specific fee editor:** In each Center A or B association, edit only that center's permitted consultation mode, consultation and follow-up fee kind, integer-minor-unit amount formatted as ₹, effective date and current/previous versions, approvals and source reference. Show when a price starts/ends and whether it is currently approved; prevent overlapping periods and show old fees immutable. No Paid, Received or Booked status. A Center A staff member cannot edit B's current fee or global doctor registration without a specific CG-01 grant.

**Privacy and state:** License proof and private phone are restricted; public profile later shows only explicitly approved name/specialty/qualification/experience/public professional contact/consented image and relevant current center fees. Global doctor suspension removes all public affiliations; pausing only Center A doesn't alter Center B's genuine status. CG-15 schedule/availability and CG-17 benefits are *not* part of fee-editor screens.

## 6. US-004 — real public discovery and native directory

**Source-backed filter inventory:** Actual category dictionary contains the **nine illustrated** types: Polyclinic, Diagnostic Center, Dental Clinic, Medical Laboratory, Hospital/Nursing Home, Pharmacy, Orthopedic, Homeopathy and Ayurvedic. This categorization is not automatic pharmacy checkout, insurance service, lab booking or nursing theater operations. Center filters include name, state/district/block/PIN, provider type, actual published facility/capability, public working hours, and only real supported benefit flag **if CG-17 later provides it**. Doctor filters include name, specialty, qualification, experience, allowed current consultation fee range and actual approved center/area. Apply/Reset filters, URL-safe sort, stable pagination; human-readable chips, visible relevant results, and true "No published centers match" rather than a server-error empty array.

**Public result card:** Name, approved category, current public-safe location, true available facility/service chips, current public working hours, actual VALIDATED/approved badge if permitted, source-validated photo, approved center-specific doctor fee (₹ amount and service/follow-up mode), phone/website only with consent, "View center"/"View doctor" and optionally "Directions" to genuine coords. Map view requires actual coords and a safe route/URL; without coordinates provide address/contact instead. **No "Available now"/Book appointment before actual CG-15 schedule and slot**, no mocked star/reviews/₹ coupon/benefit percent. No date-to-slot inference from center opening hours.

**Public Android:** Native category grid/list, Center Search and Doctor Search top tabs or equivalent task-first navigation, filter sheet with explicit Apply/Reset, dynamic result count from real server, list/grid readable cards, doctor center choices and current fee, detail with contact and map action. Handle Android Back/safe areas/keyboard/long legal name/offline last-known (clearly stale) and source revision recheck. Need no camera/location permission for browsing. A suspended center disappears from authoritative reads immediately; stale native cache may show a neutral unavailable/refresh state, never a verified active provider/Book CTA.

**SEO and CG-18 boundary:** Public Next.js directly renders actual CG-14 `/healthcare/centers`, `/healthcare/doctors` and guarded detail URLs with safe canonical metadata/sitemap. This functions with **zero CMS editorial pages**; once CG-18 exists, its editor may place actual CG-14 source-safe result cards under the already approved branded landing, without changing health data. Native directory remains source-owned. CG-18 does not store a second provider fee, and CG-14 does not depend on marketing copy.
