## 3. Five sequential vertical workflows and typed endpoints

**US-001, credential verification (no patient):** `GET /api/v1/nursing/professionals/options`, `GET/POST /professionals`, `POST /professionals/:ref/credential-submissions`, `POST /:ref/submit|review|return|withdraw`, `POST /:ref/affiliations`, `GET /:ref/affiliations`. Center applicant records nurse/qualification and supplies protected verified CG-19 credential evidence using US-001-introduced registered source adapter INSIDE original CG-19 authority; configure actual CG-03 NURSING_CREDENTIAL_VERIFICATION process/case only when review policy requires, freeze revision+digest and attach authorized reviewer, original final decision applied only by guarded CG-23 finalizer. Prevent proposer self-approval when independent check required, forged professional license, reviewer revocation and same identity duplicated across centers; current affiliation approved separately. Foundation Admin and eligible native Internal Android can review same current-source evidence/actions. No CG-10 or CG-14 doctor row.

**US-002, shift availability (no patient):** `GET/POST/PATCH /api/v1/nursing/availability-rules`, `POST /availability-exceptions`, `GET /availability?center&nurse&period`. Validate real verified affiliate, timezone, local weekday/overnight windows, leave and end-exclusive UTC instants. A valid rule is a *candidate* only; do not promise booking if another center uses that nurse. Current CG-01 action, CG-14 grant/license and source version are mandatory. Keep bounded real date preview, no permanent all-day calendar rows, no future CG-15/17 dependency.

**US-003, private consented request and assignment:** `POST /api/v1/nursing/service-requests`, `GET /service-requests`, `POST /service-requests/:ref/assign|cancel|reschedule`, `GET /service-requests/:ref/visits`. Real CG-15 current patient consent, CG-14 approved center nursing service & current fee revision and actual center/home scope; snapshot approved rate and visit frequency/period. Resolve each requested visit occurrence within bounded planning horizon; assign one eligible current professional at source-affiliated center whose shifts cover the time and whose root+nurse PostgreSQL exclusion has no overlapping already-held/confirmed/in-progress visit in ANY center. Under race only one competing assignment wins; conflict returns readable `This nurse is unavailable at the selected time`. Reschedule holds original booking until new guarded reservation wins; no double exposure or phantom doctor slot. Cancellation writes source event and releases actual occurrences; no silent patient payment/refund.

**US-004, safeguarded care plan and visit delivery:** `GET/POST /api/v1/nursing/care-plans`, `POST /visits/:ref/start|complete|missed|correct`, `GET /visits/:ref/history`, `POST /visits/:ref/evidence`. Requires actual assigned visit, CG-15 consent still current, qualified current professional and center authorization. Create immutable encrypted care-plan revisions, actual visit event and optional **CG-19 original protected nursing evidence source adapter introduced in US-004**, not duplicated file bytes. Actual completion requires recorded performed time, actual professional/independent clinical review where specified, correct request revision, and agreed visits/period outcome; no speculative auto-Completed from time elapsed. A past plan edit or two concurrent completion calls cannot override new source; signed correction/retraction is separate reference-based event. A nurse cannot view Center B unrelated patient, and Foundation supervisor cannot read protected plan merely from root admin role. Public Android may show *own* released limited visit status via actual CG-15 patient authenticated purpose, not unapproved clinical notes.

**US-005, original reports and optional financial signal:** `GET /api/v1/nursing/reports/summary|visits|appointments` reads only real reserved/accepted/performed source rows with as-of and actual restricted root+center scope, no CG-20 dependency. Report booked vs assigned vs visited vs medically reviewed/completed; `COMPLETED != PAID`, and schedule due does not mean visited. Optional actual verified complete source emits `CG23_NURSING_VISIT_COMPLETION` via narrow original CG-17 adapter registered **inside CG-17's existing source registry**, validated root+center+patient, accepted CG-14 fee/policy, source revision/digest and signed completion; CG-17 alone determines approved assistance and source idempotent obligation, CG-09 alone records Foundation journal when authorized. Missing CG-17 policy = `No Foundation assistance configured`, no assumed discount. Real correction/reversal links to original effect; no second finance ledger and no patient money from nurse text. Actual due-visit reminders only where opted-in/current consent, original CG-19 notification owner, bounded due-key, and only if effective ERP ON with actual eligible due work.
