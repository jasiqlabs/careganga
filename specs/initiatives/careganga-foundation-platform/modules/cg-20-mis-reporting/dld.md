## Canonical CG-20 relational data and transaction contracts

All CG-20 rows have a real CG-01 Foundation-root FK and composite same-root uniqueness/FKs; opaque internal IDs are hidden in UI. Keep one versioned additive PostgreSQL migration history, validated NOT NULL/UNIQUE/CHECK, bounded JSON schema and optimistic compare-and-swap. Source records and report file bytes are NOT copied to CG-20 tables.

| Owned table | Exact function and invariants |
| --- | --- |
| report_definition | Versioned immutable stored CUSTOM or SAVED_STANDARD safe source catalog contract, selected allowlisted fields, filters, groups, sort, chart/pivot, definition digest, real creator/root, schema version and revision; built-in standard catalog need not be seeded as new rows. UNIQUE(root,definition_id,revision). Never store SQL/expression strings or raw source records. |
| saved_report | Owner account, report_definition current revision pointer, name, PRIVATE by default, limited authorized visibility, expected version/CAS, retired_at; UNIQUE current normalized name per root+owner as needed. Copy never clones original recipients, source grants or protected fields. |
| report_run | Requester, real root, frozen definition revision/source contract, server scope/request digest, source cutoffs, origin schedule/due key optional, state QUEUED/RUNNING/READY/EMPTY/FAILED/EXPIRED/REVOKED, summary counts/digest, protected CG-19 artifact reference, error class, expiry and progress; UNIQUE(root,requester,idempotencyKey) for on-demand, UNIQUE(root,schedule,due_at,definition_revision) for scheduled. No persistent unrestricted row dump. |
| report_schedule | Root, owner, saved report, bounded validated cadence/IANA timezone/local time, next_due_utc, active PAUSED/DISABLED/ACTIVE, recipient-policy reference, revision/lease; CHECK cadence/time; indexed (next_due_utc,id) for ACTIVE rows only; no schedule pointing at retired or non-authorized report. |
| report_delivery_attempt | One original scheduled report_run+recipient account+channel/source event, CG-19 notification source ref, status QUEUED/SENT_PENDING/CONFIRMED/SUPPRESSED/FAILED, bounded attempt/next_retry/lease and redacted provider class; UNIQUE(root,run_ref,recipient_ref,channel), no blanket recipient emails. |

**Indexes/races:** root+owner+updated and narrow scope for saved pages, root+requester+timestamp for run history, status/expiry partial for eligible cleanup, next-due partial for schedules and due/retry partial for recipient attempts. Direct DB constraints plus scoped locks or expected revision prevent concurrent duplicate run/delivery and stale report edits. Real root/actor required for every list/options/report/export/download. EXPLAIN, restore, migration rollback, RLS role/pool checks and cross-center data tests remain NOT_RUN for independent database/security QA.
