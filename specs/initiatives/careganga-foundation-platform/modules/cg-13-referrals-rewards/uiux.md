## 3. Screen interaction blueprints and states

**B11/B13 configuration:** after authentication/role, B11 seven example rank card statuses (only if really configured), rank history/tiers/eligible counts, selected tabs and actual filtered table; B13 drawer preserves original labels but shows exact effective date/eligibility basis, points per actual verified referral, minimum claim, versioned rank thresholds, nonexpiring default, optional expiry only with explicit approved rule. “Points-to-INR Conversion” clearly identified as **informational reference, no withdrawable currency**. Preview of how rules apply to next *new qualifying* source; don't rewrite prior accepted points or ranks. Save checks overlapping thresholds, invalid decimal, missing configuration and simultaneous revision; real Cancel/Confirm with unsaved change warning, current backend outcome.

**B14–B16 products:** preserve original teal hero, KPIs, tabs/categories/search/cards and right drawer; DIGITAL does not require stock, quantity or store, and a recipient may receive an approved digital recognition only if actual fulfillment method works. PHYSICAL requires actual permitted CG-12 ACTIVE item/store and **read-only** real available-now/held stock; when CG-12 down, display “Availability unavailable—cannot redeem” not “0 in stock” or a false green badge. Don’t infer shipping/tracking courier or gift card API. Allow restricted image selection from current CG-19 source or safe approved URL and accurate content preview. Deactivated/updated price does not change existing approved redemption snapshot. Admin-only filters, age/branch/role sensitive rank info and duplicate action feedback consistent with original source.

**US-002 own referral:** genuine CG-04 member/volunteer sees one opaque referral code + share link, “Pending qualification” after application, “Qualified” only when original CG-04 approved/paid-or-valid-zero-fee member or approved active volunteer event arrives; duplicate/circular/self-referral refusal is human-readable without disclosing applicant account/name. Correct source reversal shows reversed earned points and historical rank change; when already spent, staff sees guarded deficit review, not negative public wallet or phantom money debt. Public user's own credits/history are private even if referral code publicly shareable; an anonymous link resolver never displays person details.

**US-003 redemption:** display `Earned | Available | Held | Redeemed` distinct, rule eligibility and recipient-confirmed status. Confirm dialog has genuine item/title, frozen point price, current eligible relationship and source units without supplier data. If two people claim one last item, losing user gets truthful out-of-stock/unavailable and unchanged available points. Pending CG-03 review/points hold/stock held/issued-to-staff/handover-confirmed/digital-provisioned/returned/reversed use separate readable labels and accessible icons not only green/red. A points hold is **not Redeemed**; a stock issue to handler is not “Delivered to you”; cash INR equivalent is not withdrawable. A lost response shows “Checking your previous request—do not submit again” and resolves the same source key, no repeated debit; cancellation/return/reversal leaves immutable history and correct hold release.

**Access/empty/offline:** loading vs genuine empty programmes/zero points/no products vs CG-04 not eligible vs CG-12 temporarily unavailable vs permission revoked vs request processing/unknown response; allow editing drafts but not completing an irreversible offline redemption. Source options exclude inactive/wrong-root store or member, no fabricated category/stock/recipient. Keyboard/focus/200–400% Web responsive, native TalkBack/large font/Back/modal focus; restricted shared deep links, safe file/artwork access, no PII in toast/notification/SSR cache. Page reports match current chosen scope, cards and category filters; no fake dataset and no phantom new CG-18 page dependency.
