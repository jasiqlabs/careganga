## 3. Authoritative PostgreSQL model and migration specification

All CG-18 persistent rows have a server-derived **foundation_root_id** from CG-01; no client-provided root is trusted. Use UUID PKs (hidden from normal UI), timestamp with time zone for instants, normalized reserved-slug checks, bounded TEXT/JSONB with typed DTO validation, optimistic BIGINT versions, and same-root FK/UNIQUE constraints. The following are **one canonical set**, not alternatives/shadow tables. Naming may follow existing CG-01 ORM migration conventions, but semantics/constraints are mandatory and any name change must be reflected consistently before coding.

| Table and essential columns | Invariants / ownership |
| --- | --- |
| cms_page(id, foundation_root_id, slug, kind, draft_revision_no, version, created_by, created_at, archived_at) | UNIQUE(root, normalized_slug); kinds HOME/ABOUT/IMPACT/COMPLIANCE/GALLERY/ARTICLE/CONTACT/HEALTHCARE/OTHER; CHECK nonempty safe slug, root/current author from CG-01. Reuse shared audit envelope where already implemented, not a second platform-wide audit store. |

**Schema rules:** CHECK one published page target matches its current root, immutable revision and actual approved decision digest; use app/domain state guards AND composite FKs; deferred DB validation or guarded transaction prevents an EFFECTIVE pointer to an unapproved/unavailable revision. FK on delete is RESTRICT for published/approved history; archive/inactivate and append new revision, never cascade-delete evidence. Database unique scope must use *normalized* slug; slug aliases/redirects are explicit approved safe pages and do not cause open redirects. Foreign root, forged approver and expired media are denied for list/read/public search/sitemap, not merely for mutation. For team biographies and testimonials, preserve consent/public-use proof, current rights state and revision history without adding CG-10/04 FK before their owners exist. Do not store private CG-19 upload tokens in CMS JSON.

**Migration sequence:** (1) identify exact existing CG-01 root/auth, CG-03 case and CG-19 file APIs and product ORM; (2) create CG-18 tables with NOT NULL/root and scoped CHECK/UNIQUE/FKs, current-publish indexes and account-scoped audit; (3) add genuine CG-03 CMS_PUBLICATION owner source/process registration and CG-19 CMS draft media adapter using their existing migration/typed-facade conventions; (4) bootstrap **no demo content and no future records**; empty Home/editor state is honest and first author may create it; (5) backfill only if **real existing CG-18 data** is discovered, never synthesize records; (6) verify migration up, rollback on disposable DB, index presence, data backup/restore, and old Web/Android API compatibility. Multi-developer migration ordering is serial at integration. Production restore requires owner authorization. SQL migration, representative EXPLAIN and restore have NOT been run.

**Indexes/access:** UNIQUE(root,normalized_slug); UNIQUE(root,page_id,revision_no); INDEX(root,kind,archived_at), INDEX(root,page_id,created_at DESC), INDEX(root,state,effective_at) for publish/due, INDEX(root,sort_order) for public ordered sections, bounded article/gallery category/date/slug queries; avoid index per JSONB field without measured filters. Public page read should find one current pointer plus finite approved sections/assets, not N+1 files per card. For source file rights use one bounded CG-19 batch facade, not a separate remote request for every tile. Expected cardinalities/traffic are NOT_VERIFIED; implementation measures sample sizes/EXPLAIN and sets bounded limits.

## 4. Approval, publication, cache and failure transactions

**Draft→Submit:** CG-18 validates current CG-01 editor/root, title, layout, safe CTA, page-kind schema, source rights and file upload status. Preview is a **private authenticated** HTML/JSON projection with noindex/no-store, short-lived permission check, no leaked public URL. Freeze immutable revision+digest, insert one CG-03 CMS_PUBLICATION case using **CG-03's owner facade** introduced in US-001. If no actual process exists, return UNAVAILABLE, not approved. The CG-03 case points to root, source ID, exact submitted revision and digest. Editing afterward creates another revision; old approval cannot authorize it.

**Decision→Publish:** CG-03 owns reviewers, process version and final decision. CG-18 publisher checks current independent CMS_PUBLISH permission, real final CG-03 decision matching *exact* revision/digest, correct proposer-reviewer separation, content/consent/file rights, approved SEO/route and current page version. A scheduled future revision creates durable cms_publication_due, not an immediately public page. For immediate publication, run a **short shared PostgreSQL transaction** under stable lock order (source/approval proof rows via typed read-only locked CG-03 facade, valid CG-19 status rows through its locked read-only proof facade as needed, then CG-18 page/effective pointer), write accepted publication/audit/outbox and commit. If the owner facades cannot provide same-transaction freshness, fail closed and design an explicit reviewed revision-proof + revocation fence; a pre-checked stale decision is not sufficient. Do not call CDN/object store/HTTP/email inside DB lock. Duplicate publication key with same digest yields accepted original effect, with different digest yields CONFLICT. For unknown commit outcome, query accepted source key before resubmitting; never flash success before commit confirmation.

**Unpublish/revoke/expiry:** Authorized withdrawal is one transactional pointer removal + audit + outbox. Public APIs must revalidate effective revision and data rights before serving; **no shared private/draft cache**. Public pages may be cached only as allow-listed effective content with ETag derived from current effective generation, revalidation on load and explicit publish/withdraw invalidation. For person-consent, legal/80G certificate validity, and revoked private/public media, prefer no-store/mandatory origin revalidation (no stale-while-revalidate); CDN invalidation is an additional aid, not the only privacy guard. SSR sitemap/search indexing excludes draft/unpublished/expired; remove or 404/410 withdrawn pages and update sitemap/robots. Public Android must not persist protected images/expired tax claims as evergreen offline content: show verified last-updated/offline state and revalidate current eligibility on next view; do not show a working withdrawn CTA from stale navigation.

**Scheduled publisher:** A bounded due-only worker processes eligible rows with DB-claim SKIP LOCKED/lease, cap batch/concurrency/attempt count and backoff; revalidates case, source revision, current publisher/root policy, media status, current route and expiry at effective time. A public visibility change or revoked approval preempts schedule. Zero due jobs means no per-tenant scans, empty webhooks or always-on tenant polling. Restart recovery reads due rows, dedupes by immutable publication key, and safely reconciles unknown outcome. Dead due rows have redacted operator diagnostic/audit; they do not silently publish.

**Navigation:** CG-18 owns three independently chosen desired flags inside its CMS publication (same review, revision and CAS mechanics). Public projection computes Login/Profile only from real CG-01 public session capability, and Member/Volunteer from real CG-04 route availability once CG-04 later integrates; no false self-registration route, CG-21 setting clone or authorization bypass. A user may enter only if actual CG-01/04 target guards pass even if the link is visible.

**Public contact/notices:** The Contact editor publishes a layout/actual valid CG-19 endpoint; anonymous submit is POST to CG-19's existing abuse-throttled contact API and returns an opaque receipt, never via CG-18 contact_message. Public notice publication requires safe CG-19-approved source, independent CMS editorial decision and actual valid notice expiry/audience. A sent private notice is not public. CG-19 owns original FAQ/notice/source delivery status.
