## Canonical owner and record boundaries

CG-07 owns one campaign and revision history, one donation intent/attempt and validated payment-outcome evidence, source-linked refund request/evidence and privacy-safe donation/campaign projections. CG-09 owns balanced posted journal/verified finance authority; CG-19 owns issued receipt/document bytes and template; CG-03 owns review cases; CG-18 owns editorial publication; CG-21 holds protected configured connection reference only, not payment state. The following concrete record contracts are the **single canonical implementation model** for this module; legacy draft aliases are not extra tables. Real owner keys, same Foundation-root/actual CG-02-branch isolation, normalized uniqueness, valid states and creation/update revisions are enforced by migrations and guarded commands; no unrelated patient/healthcare-center scope is imported. No owner creates a future module's master record or copies another owner's sensitive data. Platform and integration errors use safe explicit categories, not a success-shaped default.

## Concrete fundraising and payment verification

`campaign(root_id,id,branch_ref_nullable,code,category,source_project_ref_nullable,source_event_ref_nullable,goal_minor,currency,start_at,end_at,current_revision,source_status,approval_case_ref_nullable,version)` and immutable `campaign_revision` persist the exact six wizard steps, draft/approval snapshots and original status history. Real CG-03 source decision and independently effective CG-18 publication are separate, **not** a CG-07-owned CMS publish-state table. Live fundraising net is derived only from the original CG-09 confirmed posted received/reversal events, not pledged or pending donation requests.

`donation(root_id,id,campaign_id_nullable,donor_contact_snapshot_ref_nullable,amount_minor,currency,donation_kind,status,verification_ref_nullable,finance_source_key_nullable,version)` supports genuine **general** (campaign null) or eligible campaign donation. A donor is not assumed to hold a future CG-04 member or CG-01 internal account; restricted consented payment/contact snapshots are CG-07 donation attributes, never a new reusable person master. `donation_payment_attempt` owns link/reference/method/merchant/version/expiry/request status; immutable `donation_payment_event` stores only authenticated provider identifier, correct merchant, donation/attempt and exact amount/currency/result digest. UNIQUE(root,provider,merchant,event_id) prevents duplicate verified events; mismatched replay conflicts. Manual money needs a distinct authorized verifier and original CG-09 legitimate proof/posting, not a checked client flag.

A verified external collection or authorized manual evidence creates **one pending finance-post command**, and only CG-09's confirmed immutable balanced POSTED effect produces `RECEIVED_POSTED` and eligible CG-19 `RECEIPT_ISSUABLE`. If CG-19 issuance fails after money posts, display `RECEIVED / RECEIPT_PENDING` and retry issuance with the same source digest; never roll back money or show an issued receipt without CG-19 proof. `donation_refund_request` belongs to CG-07 as source intent/outcome; CG-09 owns the financial reversal, and only verified refund + CG-09 reversal count against net fundraising totals. Lock original donation/verified refund total to cap concurrent partial refunds; provider succeeded but response lost is reconciled with original reference, never reissued as a new refund.

**QA:** six-step draft recovery, unauthorized publication, missing merchant, two webhook deliveries, pending payment falsely shown received, refund race, campaign closed before late receipt, donor privacy in reports and receipt amount versus CG-09 balance.

### CG-07 state machines and exact operation transitions

**Campaign:** `DRAFT` has six editable steps and can Save Draft without CG-03 case; `SUBMITTED` freezes digest and submits original `CAMPAIGN_LAUNCH` approval. `RETURNED` allows a new version, `REJECTED` cannot publish; `APPROVED` means eligible source only, then CG-18 original `CMS_PUBLICATION` approves a public-safe independent editorial placement. `PUBLISHED` requires current live source status, publication revision, period/branch/media rights. `PAUSED/CANCELLED/CLOSED/WITHDRAWN` removes Donate CTA from Web/Public Android even if old CG-18 cache remains; historical donations/receipts survive. Old case/digest cannot approve a changed target/beneficiary estimate/goal/media.

**Donation:** `DRAFT` → `PAYMENT_REQUESTED`/`LINK_READY` → `PENDING_VERIFICATION` → `VERIFIED_RECEIVED` → `PENDING_FINANCE` → `RECEIVED_POSTED`; failures/expiry terminate attempted request (without destroying correct late provider evidence). A signed provider callback must verify current configured merchant, actual signature/timestamp/unique replay key, provider-backed amount/currency/reference and source donation; **return HTTP acknowledgment after durable event capture** and ensure old/late valid events converge safely. CG-09 `postDonationReceived(root,sourceKey,digest,amount,currency,evidenceRef)` is idempotent. When finance confirms, public net progress changes; if finance outcome unknown, lookup original source key and present `RECONCILIATION_PENDING`. Never retry charging donor after a lost response; do not create an unbounded retry worker.

**Manual money:** A17 `Save Draft` only captures data. Current authorized cashier can submit a cash/bank/cheque/NEFT proof; a distinct current configured approver/finance verifier authenticates actual received money under CG-09 policy and real CG-03 case only when the policy requires, then posts exactly once. The user-entered bank reference or cheque image alone is **not** verified received cash. If no configured online merchant, online Generate Payment Link is disabled/unavailable with explanation; original manual authorization remains a separate path.

**Receipt:** After CG-09 confirms one `RECEIVED_POSTED`, CG-07 calls CG-19 `issueDonationReceipt(root,donationRef,originalFinanceRef,immutableDigest,templatePolicy)`. CG-19 validates scope, source amount/currency/merchant/donor allowed fields, one existing template/reference/number and independently verified authorized tax text; returns issued document version/checksum and protected download authorization. If doc issue is delayed, public donor shows Paid — receipt being prepared; issue/retry never changes money or generates two active receipt numbers. A17 80G-style preview is only **PREVIEW / NOT A TAX RECEIPT** when proof is absent.

**Refund:** Request authorized reason/amount and applicable CG-03 finance approval, reserve cap on original verified received remaining amount, initiate provider/manual reimbursement with original idempotency key. Provider `PENDING`/unknown isn't `REFUNDED`. Only signed confirmed external refund or verified manual payout + CG-09 `reverseDonationReceived` immutable linked posting produces `VERIFIED_PARTIAL/FULL`, updated current donor/campaign net and CG-19 retained original + linked correction/credit note where applicable. If provider confirms but CG-09 reversal is late, show `REFUND_RECONCILIATION_PENDING` and reconcile; never reissue refund to fix a lost network reply.
