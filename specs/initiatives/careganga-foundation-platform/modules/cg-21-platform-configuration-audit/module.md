## Business owner and isolation

**Owns:** One versioned platform/system settings source, integration credential **references** and verified-readiness states, restricted audit **presentation** over genuine earlier owner events, own setting/recovery audit events, and privileged backup/recovery request/proof records. **Required real predecessor:** CG-01 completed account/session/MFA/permission and authoritative access audit, not merely a design. CG-01 still owns password/session mechanics, grants, last-root protection and access audit; CG-21 may present real CG-01 security status and only call an actually delivered CG-01 protected policy operation; absent a verified mutable policy API, controls remain unavailable, never a second account/auth service. **Future owners:** CG-03/09/14/15/17/18 add genuine domain events/integrations when delivered; CG-18 controls actual public Login/Join/Volunteer visibility; no CG-03 approval case, CG-02 branch, future merchant/provider, CMS record or fake log may be needed to complete CG-21 initial work. Later owner supplies its cross-module QA. Unavailable external integration stays DISABLED/NOT_VERIFIED rather than falsely ready.

**State and invariant:** Configuration has one effective typed value per allow-listed key and real Foundation root; every accepted expected-version update writes an append-only source revision and redacted audit atomically. Integration status DISABLED/CONFIGURED_NOT_VERIFIED/VERIFIED/FAILED/UNAVAILABLE is bound to the current credential revision and actual check time; no check means NOT_VERIFIED, not payment/notification readiness. CG-21 central audit is a bounded permissioned read projection of actual CG-01 and CG-21 owner events, with unavailable feeds clearly disclosed; future owners contribute only when delivered. Recovery REQUESTED → PRIVILEGED_AUTHORIZED → RUNNING → VERIFIED_SUCCEEDED/FAILED/UNKNOWN requires a real secured backup/procedure and independently verifiable proof; no real facility yields NOT_AVAILABLE and no fictitious operation. CG-01 enforces root authority and fresh MFA; CG-21 can display actual CG-01 session/password security state but offers **mutable policy controls only when CG-01's delivered protected API genuinely supports them**, otherwise the option is explicitly unavailable rather than shadowed or invented; no CG-03 approval dependency. All query/export/options/write calls are server scope-checked, redacted, conflict-guarded and fail closed.
