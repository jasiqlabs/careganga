## Canonical CMS database, root guards, publication race and cache proof

- The one canonical original model is cms_page(root_id,id,normalized_route,page_type,editorial_state,draft_revision,current_effective_revision_id,version), cms_page_revision(root_id,id,page_id,source_digest,immutable_payload,created_by,created_at,submitted_at,case_ref), cms_section_revision(root_id,page_revision_id,section_type,structured_fields,sort_order), cms_publication_effect(root_id,page_id,page_revision_id,source_case_decision_key,effective_at,expired_at,status), cms_public_navigation_revision(root_id,revision,login_enabled,member_join_enabled,volunteer_join_enabled,status,published_at) and cms_media_placement(root_id,page_revision_id,cg19_file_ref,cg19_validated_version,public_classification,sort_order). Hero, public team biography, impact, healthcare editorial, 80G, media gallery and article are **typed page/section data using this single schema**, not parallel Hero/Compliance/Article shadow masters. Approved public notice rendering uses only a safe CG-19 source reference plus CMS publication record; contact records stay in CG-19.
- DB unique(root,normalized_route) for pages; unique(root,page_id,draft_revision) for immutable snapshots; one effective publication per page/root and monotonic effective navigation revision under short row lock/CAS, DB unique(root,page_id,source_case_decision_key) for idempotent effect. FK/root checks, bounded indexes(root,state,route/effective_at) and audit of author/reviewer/publisher; a branch/center/patient cannot choose root via caller input. Slugs are normalized and reserved routes cannot be shadowed (login/member/volunteer/privacy/healthcare API); public redirect/CTA targets use strict same-origin approved route or allow-listed HTTPS destinations, no javascript/open-redirect or unsafe rich HTML.
- Publication flow: DRAFT/SUBMITTED (private) → actual current CG-03 APPROVED matching frozen digest → SCHEDULED if future effective time, else PUBLISHED → SUPERSEDED/UNPUBLISHED/EXPIRED. The approved decision is verified before a **short single shared Postgres transaction** with owner-local read-only CG-03 decision-proof fence + CG-19 referenced evidence-validity proof and locked CG-18 source/publication pointer; no provider HTTP, object-store scan, network or CDN call while DB lock held. CG-03/19 proof-revoke transitions fence competing publication; a replay returns the original accepted effect, lost response triggers bounded source lookup. Cache invalidation/outbox is after commit and public Web/Android reject stale/withdrawn effective revisions. Public anonymous readers receive only current effective approved sanitized allow-listed payload, never draft/preview, private file reference, author email or case data. Production server must not serve stale unpublished page after revocation; bounded TTL alone is insufficient for protected withdrawal.
- Scheduled publication uses due-only bounded persisted jobs with known source revision and rechecks live CG-01 publishing policy, CG-03 proof and CG-19 referenced file right at effective time; an expired/revoked source cannot auto-publish. Zero due work means no tenant-wide or polling work. Dashboard counts strictly derive original CMS rows; no manual duplicate statistics or CG-20 fake analytics.
- Public team cards may be *original editorial approved profiles* with consent and minimal biography; never auto-copy private CG-10 salary/contact/ID. Operational CG-05 project/event, CG-14 provider/fees, CG-15 booking route, CG-17 actual support policy, CG-04 join form only become visible when their later owners introduce real typed source projections and public integration QA. CG-18 has **zero initial FKs** to these future tables. CG-18 US-004 independently publishes only generic healthcare landing/category editorial information; no provider/search/booking/benefit output in its first mandatory acceptance.
- Impact U23–U29 stores ten editorial groups and clearly dated/provenanced figures; if a source is manually entered, do not assert audited operational totals. U30 official tax/PAN/80G data is client attested with documented document issue/expiry/date and audience-approved CG-19 proof; if missing/expired, warn or unpublish substantive certification claim without silently validating tax eligibility. Beneficiary/donor/patient/volunteer private images/testimonials require genuine public rights, never infer from an internal file.
- Human-safe conflict, unauthorized, unavailable, lost-response, stale preview and provider-failure categories. Test indexed bounded public reads, no draft/cache leak, concurrent publish/unpublish/schedule, XSS/SSRF/CTA injection, expired certificate, no media leaks, same current public Web/Public Android revision and true owner integrations.
