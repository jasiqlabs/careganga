## 4. Approval, publication, cache and failure transactions

**Draft→Submit:** CG-18 validates current CG-01 editor/root, title, layout, safe CTA, page-kind schema, source rights and file upload status. Preview is a **private authenticated** HTML/JSON projection with noindex/no-store, short-lived permission check, no leaked public URL. Freeze immutable revision+digest, insert one CG-03 CMS_PUBLICATION case using **CG-03's owner facade** introduced in US-001. If no actual process exists, return UNAVAILABLE, not approved. The CG-03 case points to root, source ID, exact submitted revision and digest. Editing afterward creates another revision; old approval cannot authorize it.

**Decision→Publish:** CG-03 owns reviewers, process version and final decision. CG-18 publisher checks current independent CMS_PUBLISH permission, real final CG-03 decision matching *exact* revision/digest, correct proposer-reviewer separation, content/consent/file rights, approved SEO/route and current page version. A scheduled future revision creates durable cms_publication_due, not an immediately public page. For immediate publication, run a **short shared PostgreSQL transaction** under stable lock order (source/approval proof rows via typed read-only locked CG-03 facade, valid CG-19 status rows through its locked read-only proof facade as needed, then CG-18 page/effective pointer), write accepted publication/audit/outbox and commit. If the owner facades cannot provide same-transaction freshness, fail closed and design an explicit reviewed revision-proof + revocation fence; a pre-checked stale decision is not sufficient. Do not call CDN/object store/HTTP/email inside DB lock. Duplicate publication key with same digest yields accepted original effect, with different digest yields CONFLICT. For unknown commit outcome, query accepted source key before resubmitting; never flash success before commit confirmation.

**Unpublish/revoke/expiry:** Authorized withdrawal is one transactional pointer removal + audit + outbox. Public APIs must revalidate effective revision and data rights before serving; **no shared private/draft cache**. Public pages may be cached only as allow-listed effective content with ETag derived from current effective generation, revalidation on load and explicit publish/withdraw invalidation. For person-consent, legal/80G certificate validity, and revoked private/public media, prefer no-store/mandatory origin revalidation (no stale-while-revalidate); CDN invalidation is an additional aid, not the only privacy guard. SSR sitemap/search indexing excludes draft/unpublished/expired; remove or 404/410 withdrawn pages and update sitemap/robots. Public Android must not persist protected images/expired tax claims as evergreen offline content: show verified last-updated/offline state and revalidate current eligibility on next view; do not show a working withdrawn CTA from stale navigation.

**Scheduled publisher:** A bounded due-only worker processes eligible rows with DB-claim SKIP LOCKED/lease, cap batch/concurrency/attempt count and backoff; revalidates case, source revision, current publisher/root policy, media status, current route and expiry at effective time. A public visibility change or revoked approval preempts schedule. Zero due jobs means no per-tenant scans, empty webhooks or always-on tenant polling. Restart recovery reads due rows, dedupes by immutable publication key, and safely reconciles unknown outcome. Dead due rows have redacted operator diagnostic/audit; they do not silently publish.

**Navigation:** CG-18 owns three independently chosen desired flags inside its CMS publication (same review, revision and CAS mechanics). Public projection computes Login/Profile only from real CG-01 public session capability, and Member/Volunteer from real CG-04 route availability whenever that real owner is integrated (CG-04 and CG-18 are independent P3 peers, not guaranteed in either order; whichever merges second owns actual positive route-binding QA); no false self-registration route, CG-21 setting clone or authorization bypass. A user may enter only if actual CG-01/04 target guards pass even if the link is visible.

**Public contact/notices:** The Contact editor publishes a layout/actual valid CG-19 endpoint; anonymous submit is POST to CG-19's existing abuse-throttled contact API and returns an opaque receipt, never via CG-18 contact_message. Public notice publication requires safe CG-19-approved source, independent CMS editorial decision and actual valid notice expiry/audience. A sent private notice is not public. CG-19 owns original FAQ/notice/source delivery status.
