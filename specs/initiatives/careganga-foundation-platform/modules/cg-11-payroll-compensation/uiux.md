**C01 navigation:** a single payroll module may link original Salary Reserve, Payroll Verification, Payment Batches, Pending Approvals, Salary Payments, Salary Slips, Deductions and Payroll Reports as subviews in existing CG-11 workflows. No new independent payroll micro-app, duplicate pay table or CG-09 account page. Menu items appear **only after delivered business action** + current actor permission. Empty unavailable submenus are hidden; all cards link to actual source-filtered lists. Salary Reserve may show original CG-09-approved earmark status (not an editable CG-11 cash balance).

## 4. Interaction decisions and source-state blueprint

**Compensation setup (US-001):** choose a real current eligible CG-10 employee by safe name/branch, show current salary version/valid-from, highlight proposed HR change vs payroll-approved future effective salary and pending bank update; optional components only from authorized effective policy; show BR-defined basic/allowances/deductions/tax metadata with honest `NOT_CONFIGURED` for statutory functions not client-verified. Confirm approval risk and exact effective date, mask employee account until holder/IFSC verified. Separate outcomes DRAFT / PENDING_APPROVAL / APPROVED_EFFECTIVE / SUPERSEDED / REJECTED; do not overwrite historical salary. Other staff and normal search never see full bank/pay.

**Run wizard (US-002):** (1) Period/cycle/year/branch, (2) Fetch actual CG-10 attendance + validation with missing/ineligible per-row reasons, (3) Review frozen gross/deductions/withheld/net, (4) Submit exact run revision with CG-03 source case, (5) show authentic final approval outcome and **payment readiness** without calling payment. Every step supports Save Draft/Back/refresh/conflict, accurate totals/eligibility, double-submit prevention and source-drift warning. Late leave correction starts **separate adjustment review** with reference to frozen original. A user's cached row selection never bypasses server. Show original C05 progress/validation not unbounded "Calculating..." loop; empty data and source outage distinct.

**Reserve/batch/payment/history (US-003):** show approved payroll reserve only as CG-09 source status; CG-11 batch row per employee with `PAYMENT_REQUESTED/PROCESSING/UNKNOWN/FAILED/PAID_VERIFIED`, batch `PARTIALLY_PAID` if mixed; never label everything paid after bank ACK or one success. Confirm bank source version before releasing; changed destination invalidates pending approval and triggers safe review. C07 filters and accessible mobile own history show original snapshot plus current payment truth. C08 payslip can be generated before release only if labelled unpaid/approved; always shows accurate as-of status and never auto-mails or creates a second cash/expense. An UNKNOWN transfer reconciles its original key; a **verified failed/partial** attempt may create a separately authorized **remaining-due** transfer with a new linked key, never a second full salary payment. B48 final dues remains pending until CG-09 verified.

## 5. Required states, usability/security and visual QA

Every screen/task must design true Loading / Empty / Disabled source / Authorization denied (including post-load revocation) / Validation / Missing CG-10 attendance / No verified statutory rule / Locked period / Stale run revision / Duplicate source / Network unknown after bank submit / CG-03 reviewer conflict / CG-09 bank partial/reversal / CG-19 PDF/notification unavailable / Completed verified. Render safe plain-language decisions; no raw UUID/SQL/payment tokens or bank info in toast/report/share; protected PDF via CG-19 authorized short-lived file access. A one-page self-service payslip is readable at mobile font scaling and never public-searchable/SSR-cacheable. Web keyboard/focus/table and narrow zoom 200–400%; Android Back/gesture, large text/TalkBack, touch targets, protected background/task switcher/screenshots where appropriate, without claiming executed native QA. Accessible warning/error states never depend only on color. Original exact icon/spacings/palette must be sampled/reused through CG-01 shared tokens; source still frames cannot establish motion duration/easing.
