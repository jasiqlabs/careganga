### US-001 — Configure Foundation identity, real geography and departments/committees

Outcome: Maintain the single real Foundation legal/contact profile, geography hierarchy and Foundation-wide or approved-branch departments/committees with real permitted manager/head accounts; retain future links and public publication under their later source owners, not invented current records.
Requirements: FR-004, CG-02-BR01, CG-02-BR02, CG-02-BR06, CG-02-BR07, CG-02-BR08, CG-02-BR09, CG-02-BR10; PRD N-01/N-04/N-05/N-09/N-11/N-12/N-13.
Scope: Foundation Admin responsive Web, CG-02 NestJS business domain/API/DB and shared CG-01 role/option contracts. US-001 does not introduce an Internal Android geography/department master editor; the Android branch-manager workflow belongs to US-002. Legal profile, actual geography, Foundation-wide department/committee and active-branch-scoped department are real CG-02 records; future CG-04/05/09/10 linked masters remain later-owner integrations.
Acceptance: An authorized Foundation operator saves the real official profile, creates/filters state/district/subdivision/block hierarchy, and creates a Foundation-wide department/committee **before any branch exists**. Only after real activation may a branch-scoped department be created. Invalid level, duplicate root area/name, cross-scope parent/cycle and stale edits are rejected without mutation. The original U21–U22 theme, safe permission-based selector, clear user messages and redacted audit are mandatory.

Expected: Web displays accurate actual names, status and permitted filters; one profile and real geography/committee persist with audited revisions, **no branch, CG-03 case or CG-19 file required for this US-001 journey**.
- **US-001-QA02:** A revoked, unprivileged or out-of-scope actor uses a deep link, direct API, related selector or export → backend denies, UI shows a safe next action, no private data or mutation escapes.
- **US-001-QA03:** Two concurrent submissions or a replay/lost response → scoped row revision and unique source prevent duplicate effect, show accurate conflict/refresh.
- **US-001-QA04:** Invalid field, absent source, unavailable required owner/provider or uncertain network result → distinct field error/empty/pending/unavailable UI, no invented success, safe retry.
- **US-001-QA05:** Authorized second channel/report/related owner sees same real state; restricted read remains denied, absent future integration honestly unavailable.

Expected: PostgreSQL root uniqueness and server checks reject duplicate/cross-scope/cycle with safe inline errors; no stored partial hierarchy or deleted real head association.
- **US-001-QA08 — permissions, human errors, audit:** A revoked or unrelated admin calls profile/area/dept search, options, direct details, mutation and export. Expected: all responses enforce real CG-01 Foundation/branch scope without leaking private legal contacts or unrelated branch data; role-appropriate UI hides actions and displays “You don't have access to this department.” Restricted audit records actor/source/change and technical logs include only redacted correlation reference.

### US-002 — Complete real seven-stage branch registration, approval and activation

Outcome: Complete seven-stage draft/review/submit registration with contacts, location, documents, manager and linked resources; after required approval issue unique branch code.
Requirements: FR-005, CG-02-BR03, CG-02-BR04, CG-02-BR05; PRD N-01/N-04/N-05/N-09/N-11/N-12/N-13.
Scope: Foundation Admin responsive seven-stage branch wizard **and** permitted Internal Android branch-manager draft/submit/status journey, one shared CG-02 NestJS owner/API/DB, real CG-19 file refs and CG-03 decisions. Stage 5 uses a genuine eligible CG-01 manager; stage 6 links only existing CG-02 Foundation resources and explicitly defers CG-04/05/09/10 links to those later owners without creating dummy records. Do not add public Android branch administration.
Acceptance: A permitted real branch manager completes/saves/resumes the seven-stage form on Admin Web or Internal Android, submits mandatory authentic CG-19 photo/registration/agreements to a genuine CG-03 review and sees a correct pending/returned/rejected/approved status. Only actual final approval creates one active branch with one unique code, even with concurrent callbacks; no future employee/project/volunteer/budget data is needed. Maintain U18–U20 look and safe native response states.
