## 3. Native Public Android and public Next.js journeys

**Member path (US-001/002):** Current standalone CG-04 Join route (not blocked on CG-18) → genuine active tiers/fee/validity/benefits with version → open application and verified identity/contact/consent → choose genuine permitted CG-02 region/branch where rule allows, upload CG-19 protected evidence → clear fee due/pending/verified/failed/unknown with actual CG-09 → submit CG-03 frozen review and track own application reference/steps → when both approval and verified fee/free term exist, view actual member number/term/renewal/profile and only real CG-19 card/certificate. Returned/rejected/refunded/expired/suspended renders honest state. Public Web SSR/SEO must never index private application/detail/receipt/document routes or share private cache.

**Volunteer path (US-003):** Current CG-04 Volunteer Join → genuine U15 inputs with stepwise accessible groups and validation (optional sensitive field visually marked optional) → actual U16/U17 eligible department/availability → CG-19 proof and consent → submit once → see own application reference, returned-correction, pending review, rejected or approved current volunteer with branch; no auto member/staff/employee account or false CG-05 task. Current eligible volunteer may request a legitimate CG-09 expense against true attached bill, showing actual finance status only; no CG-04 money copy.

**Native behavior:** Public Android uses original CareGanga tokens with native stack screens, Back, TalkBack, safe area, clear keyboard/OTP/contact validation, safe local media picker with preflight permission, pending upload indicators, offline status refreshing and no WebView. Internal Android is for explicit role-allowed actual CG-05 task/visit and genuine CG-04 read, not public enrollment copy or automatic volunteer login. Start with true existing `apps/android-public` and `apps/android-internal` app entry points; no new app shell. ## 4. State, notification and permission UI details

| Condition | Web/Admin/Public Android | Authoritative source and non-bypass |
| --- | --- | --- |
| Tier deactivated while editing/registering | Form refresh/validation; preserve historical accepted price snapshot, disable new ineligible tier selection | CG-04 current tier version and guarded application submission |
| Two applications/renewals or stale edit | "Already submitted" or "Updated by someone else; refresh" with true existing reference, no second payment/member | CG-04 unique idempotent request and current CG-09 result |
| Review returned / denied | Plain status + correction action for correct applicant; no approved card or employee access | CG-03 process/decision and CG-04 current application |
| Paid but rejected | Show "Rejected — refund awaiting confirmation" until CG-09 verified refund, then "Refund completed"; never false paid/refunded | CG-09 receipt/refund, CG-03 case and CG-04 enrollment |
| CG-19 file invalid / rights revoked | Hide download or show access denied; preserve safe application draft, no fake generated card | CG-19 actual evidence/issuance status + current CG-04 source |
| Volunteer active but no CG-01 internal role | Can view own volunteer status/claim if eligible, **cannot open Internal Android private task/visit** | CG-01 role grants + real CG-05 task and CG-04 current status |
| Volunteer branch transfer/revocation | Old CG-05 volunteer options no longer selectable, private GPS unauthorized, own history only within current policy | CG-02 branch and CG-04 affiliation + CG-05 owner |
| CG-18 CTA disabled or not installed | CG-04 direct standalone route remains governed by real own eligibility; CMS published public button hidden on both Web and Android when inactive | CG-18 effective publication (if present) + CG-04 route validation |

**One identity rule:** Show legitimate business-facing membership number, application reference or volunteer business reference, never raw UUID, relation keys, database enum, bare status codes or provider/SQL messages. Name-based safe person/branch/department search/selection only; effective-root and branch current context from CG-01/02, do not guess consent/price/approval. Roles hide unauthorized action, backend rechecks and redacts. Buttons are non-inert and never claim success without persisted owner state.
