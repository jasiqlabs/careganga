# CareGanga V1 baseline

**Single schema artifact:** schema.sql (PostgreSQL 17), manifest.json (SHA-256 + actual 311 historical ledger hashes). This is the final logical schema extracted from an isolated migrated database, not concatenated migration scripts. All 12 logical catalog categories matched a second database recreated from the exported statements (see catalog-verification.json). 353 UUID defaults explicitly reference pg_catalog.gen_random_uuid so the pgcrypto extension cannot change function binding. No accounts, patients, donors, finance or other operational rows exported; only historical ledger. Root provisioning and approved CMS publication remain separate first-release operations. Do not overwrite a published baseline.

Actual PostgreSQL connector restore was executed in bounded batches, not via the single-transaction node installer; production role/ACL, Hostinger packaging and exact full command, rollback, restart and upgrade runtime acceptance remain required. Catalog comparison excludes provider physical metadata and environment-specific ownership/privileges. Source-generated SQL must pass release checksum and full local QA before deployment. Native pg_dump generation remains an offline recovery/reference tool for an explicitly reviewed replacement before first release, not a Hostinger dependency. See [Hostinger setup](../../../../docs/deployment/hostinger-greenfield-database.md).

**Atomic restore verified:** Exact committed schema blob executed as a whole in one PostgreSQL transaction on a third empty QA database; all 12 catalog fingerprints matched, no non-ledger rows. See catalog-atomic-verification.json. Node CLI and Hostinger qualification remain separate.
